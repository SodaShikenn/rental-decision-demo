# Rental Helper

**候補を比べて、自分に大切な条件を見つける。**

賃貸物件の画像や掲載リンクから、候補の違いと根拠を整理し、対話を通じて希望を具体化するツールです。最初に「暮らしの希望」を作文する必要はありません。候補を見ながら条件を確認し、内見や不動産会社への相談に使えるメモを作ります。

## 採用担当者の方へ

このプロジェクトでは、物件情報の抽出だけでなく、「候補はあるが、何を優先するか決められない」という入居者の課題を扱っています。出典付きの比較から質問を作り、利用者が確認した希望だけを判断材料にします。不足情報や別の部屋の価格を、確定した情報として扱いません。

## 機能の入口

PCでは上部のタブ、スマートフォンでは **「機能を選ぶ」** から移動します。各ページには対象の候補と操作手順があります。切り替えても入力途中の内容や取得結果は保持されます（地図情報は再読み込みで消えます）。

| タブ | できること |
| --- | --- |
| 候補比較 | 画像・リンクの追加、数値比較、AIとの希望整理 |
| 通勤 | 主要駅メニューと朝8時到着・夕18時帰りの経路確認 |
| 駅・買い物 | 掲載の徒歩時間とMapsの経路を照合 |
| 余暇 | 公園・ジム・カフェから使いたい場所を考える |
| 口コミ・内見 | 建物の口コミと本人の内見記録 |
| 暮らしの試算 | 出勤頻度を変えて費用・通勤・余暇の違いを見る |
| 条件メモ | 希望と確認事項を編集・コピー |
| 共有・出力 | プレビュー、HTML保存、期限付きリンク |

オンライン調査・Maps・AI・共有リンクにはAPIの接続が必要です。[各ページへの直接リンク](README.md#find-a-feature) · [画面設計](docs/UI_DESIGN.md)

## 3つの操作で体験する

比較ワークスペースでは「費用・広さ・駅と買い物・設備と契約・一覧」を切り替え、候補を見ながら横のパネルで希望を整理できます。スマートフォンでは2件を選んで比較し、下のボタンから質問を開きます。画像を押すと拡大できます。現在の版を操作するには[ローカル起動](docs/DEVELOPMENT.md#run-locally)を使います。

| 01 比較する | 02 希望を整理する | 03 メモを持ち出す |
| --- | --- | --- |
| [![候補比較](docs/images/compare.png)](docs/images/compare.png) | [![希望の確認](docs/images/discovery.png)](docs/images/discovery.png) | [![条件メモ](docs/images/memo.png)](docs/images/memo.png) |

<details>
<summary><strong>01：候補の違いと、情報の根拠を見る</strong></summary>

月額や初期費用を押すと、内訳と出典を確認できます。画像・リンクから追加でき、不明な項目を残したまま比較を始められます。OCRの詳細は必要なときに開きます。

GRAN PASEO明大前Ⅳは賃料・部屋番号のない建物図面です。同じ建物の102号室の掲載を根拠に「参考 12.3万円/月」を表示しますが、候補の部屋と一致していないため予算判定には使いません。API設定時は不足する月額情報を自動調査し、同じ建物・住所・部屋の現在の募集条件が確認できた場合だけ補完します。

</details>

<details>
<summary><strong>02：具体的な違いから、希望を一つずつ確認する</strong></summary>

AI相談は候補を分析してから質問し、回答をもとに希望を提案します。利用者が承認するまで条件に反映しません。迷った場合は保留でき、後から考え直せます。

「AI 分析」から相談できます。APIなしで試す場合は「費用 → 比較から選ぶ」で、月額の上限と重要度を選びます。確認した条件に対して、候補ごとの適合・違い・不明点が表示されます。スクリーンショットは実際の数値質問の操作であり、架空のAI会話ではありません。

</details>

<details>
<summary><strong>03：内見・相談に使えるメモを持ち出す</strong></summary>

「条件メモ」には確認した希望、選んだ設備、契約前に聞きたいことがまとまり、編集・コピーできます。候補・画像・回答・メモはIndexedDBでこのブラウザに保存します。

地図の観測結果と、それを含む会話は一時的です。承認済みの希望は残ります。メモのプレビュー・HTML出力・1〜7日で失効する共有リンクと削除に対応しました。リンク共有はAPIサーバーが必要です。

</details>

## 現在の実装状況

| 機能 | 状態 |
| --- | --- |
| 画像・リンク・手入力による候補追加 | 実装済み。OCR・リンク調査にはサーバーが必要。 |
| 比較・費用内訳・出典・用語辞典 | 実装済み。サンプルは記録済みデータ。 |
| 不足する月額情報の自動調査 | 実装済み。別室・過去・矛盾する募集条件を区別。 |
| 駅・買い物への徒歩確認 | Geocoding・Places (New)・WALK Routesを接続。以前のローカル実接続確認は成功。 |
| 候補に基づくAI相談 | 実装済み。出典参照・希望の明示的な承認あり。実会話の品質評価は継続課題。 |
| 希望との比較・メモ・端末内保存 | 実装済み。再読み込みで復元。 |
| 勤務先への通勤・シナリオ比較 | 主要8駅、所在地に応じた初期候補、8時到着・18時帰り、独立した往復取得を実装。Google Routes API は日本の公共交通に非対応。徒歩は実測成功、電車の時間比較には別プロバイダが必要。 |
| 余暇の希望発見 | 公園・ジム・カフェを取得してから頻度・重要度を確認。公園と徒歩経路の実接続は成功。 |
| 建物地点の口コミ・自分の内見記録 | 建物の一致、作者・日付・出典を保持。投稿者の居住は未確認。実例では建物を一致できず、別地点の口コミを取り込まなかった。 |
| 共有 | 内容プレビュー・HTML出力・期限付きリンク・削除。公開リンクにはバックエンドの公開が必要。 |

2026年9月22日の検証は**191テスト成功**（フロント96・サーバー95）、実OCRの2テストはスキップ。ブラウザでは確認操作・保存・モバイル・出典表示などを検証しています。直近のGemini実接続では混雑エラーが発生しており、完全な実接続品質や利用者への効果を実証したとは主張していません。

## このプロジェクトで示す取り組み

- **課題設定：** OCR検査中心の画面を、候補比較と希望の発見を中心とする体験に変更。
- **フルスタック開発：** JavaScript ES Modules、FastAPI、構造化スキーマ、外部API、IndexedDBを接続。
- **AIの扱い：** 根拠ID・物件照合・明示的な承認・古い応答の無効化・障害時の代替操作。
- **UI/UX：** 比較と質問を同時に表示、確認した希望の表示、モバイルの2件比較、キーボード操作、必要に応じて開く詳細。
- **検証と運用：** ロジック/APIテスト、プロバイダのスタブ、ブラウザ確認、Docker、GitHub Actions。
