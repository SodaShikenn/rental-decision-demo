# NEST / rental decision prototype

賃貸物件のスペックを、利用者の日常動線と妥協条件を踏まえた意思決定へ変換する、説明可能な分析チャットボットのフロントエンド・デモです。

## できること

- 月額予算と優先条件（短い通勤、夜の買い物、静けさ、作業空間）から候補を再順位付け
- 各物件について、利点・トレードオフ・確認すべき事項を提示
- 賃料推移と居住者レビューを表示（いずれも**デモデータ**）
- 条件変更について対話で説明する分析チャット（ルールベース）
- Google Maps JavaScript APIを設定した場合の地図表示

## 現在のデモ範囲

このリポジトリは、要望を聞き出し、候補と妥協点を説明する体験の検証用です。目的地、物件、経路、賃料履歴、レビュー、施設評価は固定のデモデータであり、実在する物件・人物・取引を示しません。Google Maps の接続は地図表示までで、実経路・周辺施設検索は未接続です。

## ローカルで開く

依存関係はありません。リポジトリ直下で次を実行し、`http://localhost:4173` を開きます。

```bash
python3 -m http.server 4173
```

## Google Maps API を接続する

1. `config.example.js` を `config.js` にコピーします。
2. `googleMapsApiKey` に、HTTPリファラーで制限したGoogle Maps JavaScript APIキーを設定します。
3. Maps JavaScript API を有効化します。経路を実データにする場合は、利用するRoutes API等も別途有効化します。

`config.js` は `.gitignore` の対象です。キーをコミットしないでください。

## 実サービスで必要な外部連携

|目的|候補となる連携|実装上の扱い|
|---|---|---|
|物件の表示|契約・再利用許諾を得た物件データ|物件ID、賃料、住所、間取り、掲載時点を保持する|
|住所を地図に置く|Geocoding API|住所またはPlace IDを座標へ変換する|
|地図の表示|Maps JavaScript API|ブラウザ側。HTTPリファラー制限を掛けたキーのみを使う|
|通勤・日常動線の比較|Routes API の `computeRouteMatrix` / `computeRoutes`|サーバー側で候補×目的地の時間・距離を計算し、曜日・出発時刻・交通手段を比較条件に残す|
|夜の買い物・医療・保育など|Places API (New) の Nearby Search / Place Details|利用者が選んだ施設カテゴリ・半径・営業時間を根拠とともに表示する。取得項目は必要最小限にする|
|賃料履歴と居住者レビュー|再利用許諾済みのデータ提供元|掲載賃料と成約賃料を混同しない。投稿者の個人情報、誹謗中傷、検証不能な評価は扱わない|

Maps JavaScript API はブラウザから利用するため、キーそのものを秘密情報として隠す方式ではなく、HTTPリファラー制限とAPI制限を適用します。一方、物件データ、Routes API、Places APIへのアクセスは、権限・利用量・返却データを統制できるサーバー側のAPI経由にします。

Google Maps Platformの仕様は変更され得るため、実装前に [Maps JavaScript API のセットアップ](https://developers.google.com/maps/documentation/javascript/get-api-key)、[Routes API](https://developers.google.com/maps/documentation/routes)、[Places API (New) Nearby Search](https://developers.google.com/maps/documentation/places/web-service/nearby-search)、[Geocoding API](https://developers.google.com/maps/documentation/geocoding) の公式ドキュメントと、各データ提供元の利用条件を確認してください。

## 最初に聞くべき要件

比較精度より先に、利用者に次を選んでもらう必要があります。

1. **必須条件**：月額総額、入居時期、広さ、通勤可能時間、ペット可否など
2. **日常動線**：平日・休日の目的地、出発／帰宅時刻、交通手段、買い物頻度
3. **重みと妥協条件**：「家賃を1万円下げるなら通勤を何分まで延ばせるか」のような境界
4. **説明の根拠**：各スコアの出典、取得日時、欠損値、確認すべき内見項目
5. **プライバシー**：勤務先・住所・生活リズムは任意入力とし、目的達成後に保持しない

## データの取り扱い

このデモに表示する物件、掲載賃料推移、居住者レビュー、施設評価はすべて架空のデモデータです。実運用では、次の条件を満たすデータソースに差し替えてください。

- 物件情報・賃料履歴・レビューの再利用を許諾する公式APIまたは契約済みデータ
- 利用者が自ら選択・同意して提供する生活リズムと優先条件
- レコメンド理由を表示できる評価・比較ロジック
- 住所、通勤先、行動履歴などの個人情報を最小化する設計

第三者の不動産サイトや口コミサイトを、許可なくスクレイピングする想定はありません。
